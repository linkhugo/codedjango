Prerrequisitos

ComponenteVersión mínimaVerificar con
Ansible2.14ansible --version
Python3.8python3 --version
f5networks.f5_modules1.20.0ansible-galaxy collection list f5networks.f5_modules
F5 BIG-IP TMOS14.1+Consola BIG-IP: show sys version
Acceso HTTPS al BIG-IPpuerto 443curl -k https://<IP>/mgmt/tm/sys/version
Sin SSH al BIG-IP. El playbook corre completamente en el controller Ansible y se conecta al BIG-IP via HTTPS (iControlREST). No se requiere configurar SSH en el dispositivo.

Usuario requerido en el BIG-IP

El usuario configurado en ansible_user debe tener rol Administrator en el BIG-IP. Si el BIG-IP ya usa AD/LDAP como fuente de auth, se puede usar f5_auth_provider para especificar el origen.

Instalación

1
Instalar la colección f5networks
ansible-galaxy collection install -r requirements.yml

# O directamente:
ansible-galaxy collection install f5networks.f5_modules

El archivo requirements.yml en la raíz del proyecto ya declara la versión mínima requerida.

2
Verificar la instalación
ansible-galaxy collection list f5networks.f5_modules

Debe mostrar versión ≥ 1.20.0.

Configurar el Inventario

El inventario define los dispositivos F5 y cómo agruparlos. Edita inventory/hosts.ini.

Un solo dispositivo (caso simple)

[f5_devices]
f5-prod-01   ansible_host=192.168.1.100

[f5_devices:vars]
ansible_connection=local
ansible_user=admin

Múltiples entidades (MEX / USA / PER)

# El inventario solo lista los hosts; la entidad NO va aquí.
[f5_devices]
mex-lb01   ansible_host=10.1.1.10
usa-lb01   ansible_host=10.2.1.10
per-lb01   ansible_host=10.3.1.10

[f5_devices:vars]
ansible_connection=local
ansible_user=admin

La entidad se pasa al ejecutar con -e entity=<MEX|USA|PER>, que carga entities/<entity>.yml. Una corrida por entidad, acotando con --limit:

ansible-playbook setup.yml -e entity=MEX --limit mex-lb01 --ask-vault-pass
ansible-playbook setup.yml -e entity=USA --limit usa-lb01 --ask-vault-pass
Las variables que cambian por entidad (AD, DNS, NTP, timezone, remote roles) viven en entities/<entity>.yml. Lo compartido por todas las entidades va en inventory/group_vars/f5_devices.yml. Si olvidas -e entity=..., el playbook falla con un mensaje claro.

Configurar Variables del Sitio

Las variables se reparten en dos lugares: lo compartido por todas las entidades en inventory/group_vars/f5_devices.yml, y lo que cambia por entidad en entities/<entity>.yml. Todas sobreescriben los defaults del rol.

group_vars/f5_devices.yml — compartido por todas las entidades

---
# Valores compartidos entre todos los F5

# Fuente de autenticación
f5_auth_type: "active-directory"   # o "ldap"
f5_auth_default_role: "no-access"

# Banner SSH
f5_sshd_banner_text: "AUTHORIZED USE ONLY. Unauthorized access is prohibited."

# IPs/redes permitidas para gestión (SNMP va por entidad, ver abajo)
f5_httpd_allow:
  - "10.0.0.0/8"
f5_sshd_allow:
  - "10.0.0.0/8"

# Management route (NS_STD_026) — ruta fija; solo se define el gateway
f5_mgmt_gateway: "10.10.1.1"

# Color de advisory banner (NS_STD_002)
f5_advisory_color: "green"    # default; por host en host_vars: blue/orange/yellow según rol

entities/MEX.yml — variables que cambian por entidad

Se carga con -e entity=MEX. Existe un archivo equivalente por entidad (MEX.yml, USA.yml, PER.yml).

---
# Variables específicas de la entidad MEX

# Servidores AD (2.2.2)
f5_auth_servers:
  - "dc1.mex.corp.com"
  - "dc2.mex.corp.com"

# DNS (NS_STD_010)
f5_dns_servers:
  - "10.1.1.53"
  - "10.1.2.53"
f5_dns_search:
  - "mex.corp.com"

# Subredes permitidas para SNMP (2.6.1)
f5_snmp_allowed_addresses:
  - "10.1.0.0/16"

# Usuarios SNMPv3 (2.6.3) — MEX usa 3; passwords en el vault
f5_snmpv3_users:
  - name: "nms_mex"
    auth_password: "{{ lb_snmpv3_nms_mex_auth_password }}"
    priv_password: "{{ lb_snmpv3_nms_mex_priv_password }}"
  - name: "monitor_mex"
    auth_password: "{{ lb_snmpv3_monitor_mex_auth_password }}"
    priv_password: "{{ lb_snmpv3_monitor_mex_priv_password }}"
  - name: "backup_mex"
    auth_password: "{{ lb_snmpv3_backup_mex_auth_password }}"
    priv_password: "{{ lb_snmpv3_backup_mex_priv_password }}"

# NTP (2.5.1)
f5_ntp_servers:
  - "ntp1.mex.corp.com"
  - "ntp2.mex.corp.com"
f5_ntp_timezone: "America/Mexico_City"

# Remote role groups AD (NS_STD_016/017)
f5_remote_role_groups:
  - name: "netdeck_ns"
    line_order: 100
    attribute_string: "CN=netdeck_ns,OU=Groups,DC=mex,DC=corp,DC=com"
    assigned_role: "manager"
    remote_access: true
    terminal_access: "tmsh"
    partition_access: "all"
Timezones por entidad: MEX → America/Mexico_City, USA → America/New_York, PER → America/Lima.

Configurar Credenciales (Vault)

Las contraseñas nunca deben estar en texto plano. Usa ansible-vault para encriptar el archivo de credenciales.

1
Crear el archivo vault
ansible-vault create inventory/group_vars/f5_devices.vault.yml

Se abrirá un editor. Agrega las credenciales:

---
ansible_password: "TuContraseñaAdmin"
# Un par auth/priv por cada usuario de f5_snmpv3_users (entities/<entity>.yml)
lb_snmpv3_nms_mex_auth_password: "ContraseñaSNMPv3"
lb_snmpv3_nms_mex_priv_password: "ContraseñaSNMPv3"
lb_snmpv3_monitor_mex_auth_password: "ContraseñaSNMPv3"
lb_snmpv3_monitor_mex_priv_password: "ContraseñaSNMPv3"
2
Verificar que el archivo está encriptado
cat inventory/group_vars/f5_devices.vault.yml
# Debe mostrar $ANSIBLE_VAULT;1.1;AES256...
Agrega *.vault.yml al .gitignore si usas git. Nunca subas credenciales al repositorio.

Ejecutar el Playbook

Siempre pasa la entidad con -e entity=<MEX|USA|PER>. Ejecuta una corrida por entidad y acota con --limit a los hosts de esa entidad.

Dry-run (simulación sin cambios)

ansible-playbook setup.yml \
  --inventory inventory/hosts.ini \
  -e entity=MEX \
  --ask-vault-pass \
  --check \
  --diff

Ejecución real en un dispositivo específico

ansible-playbook setup.yml \
  --inventory inventory/hosts.ini \
  -e entity=MEX \
  --ask-vault-pass \
  --limit mex-lb01

Con vault-password-file (sin prompt, para CI/CD)

ansible-playbook setup.yml \
  --inventory inventory/hosts.ini \
  -e entity=USA \
  --limit usa-lb01 \
  --vault-password-file ~/.vault_pass.txt

Salida esperada (idempotencia)

Primera ejecución: las tareas reportarán changed al aplicar configuraciones.

Segunda ejecución: todas las tareas deben reportar ok — el rol es completamente idempotente.

Skip Flags — Omitir Categorías

Cada categoría tiene una variable f5_skip_*. Ponla en true para omitirla. Útil para aplicar solo ciertos checks o cuando un equipos ya tiene una categoría configurada.

VariableOmite
f5_skip_password_policy: truePolítica de contraseñas (2.1.x + NS_STD_011/022)
f5_skip_auth_source: trueFuente de autenticación AD/LDAP (2.2.x)
f5_skip_httpd: trueHTTPD / HTTPS (2.3.x + NS_STD_014/015/024/025)
f5_skip_sshd: trueSSH y timeouts de consola (2.4.x)
f5_skip_ntp: trueServidores NTP (2.5.1)
f5_skip_self_ip: trueSelf IPs allow-service + self-allow defaults (2.5.3 + NS_STD_013)
f5_skip_named: trueServicio named (2.5.4)
f5_skip_snmp: trueSNMP v1/v2c/v3 (2.6.1-2.6.3)
f5_skip_logging: trueLog access y auditoría (2.6.4-2.6.14)
f5_skip_mgmt_route: trueRutas de management (NS_STD_026)
f5_skip_system: trueAdvisory banner, root login, hostname (NS_STD_001/002/003/012/031)
f5_skip_dns: trueDNS nameservers (NS_STD_010)
f5_skip_remote_roles: trueRemote role groups AD (NS_STD_016/017)

Ejemplo: aplicar solo SNMP y Logging

# En group_vars o directamente en la ejecución con -e:
ansible-playbook setup.yml \
  --inventory inventory/hosts.ini \
  -e entity=MEX \
  --ask-vault-pass \
  --limit mex-lb01 \
  -e "f5_skip_password_policy=true \
      f5_skip_auth_source=true \
      f5_skip_httpd=true \
      f5_skip_sshd=true \
      f5_skip_ntp=true \
      f5_skip_self_ip=true \
      f5_skip_named=true \
      f5_skip_system=true \
      f5_skip_dns=true \
      f5_skip_remote_roles=true \
      f5_skip_mgmt_route=true"

Verificación Post-Ejecución

Después de ejecutar el playbook, valida el resultado con el playbook de Hardening:

# Desde el proyecto Hardening
ansible-playbook -i inventory/hosts.ini hardening_audit.yml \
  --limit f5-cdmx-01

El reporte CSV resultante debe mostrar passed en todos los checks configurados.

Checklist de validación manual

  • Password policy: BIG-IP UI → System → Users → Authentication → Password Policy
  • Auth source: BIG-IP UI → System → Users → Authentication
  • HTTPD idle timeout = 599 s: list sys httpd auth-pam-idle-timeout
  • SSH banner habilitado: conectar por SSH y verificar mensaje
  • NTP sincronizado: show sys ntp
  • SNMPv1/v2c deshabilitado: list sys snmp snmpv1 snmpv2c
  • Hostname correcto: list sys global-settings hostname
  • Advisory banner visible en UI del BIG-IP
  • Segunda ejecución del playbook → 0 tasks changed

Problemas Comunes

Error: Connection refused / timeout

El controller no puede alcanzar el BIG-IP en el puerto 443.
  • Verificar que ansible_host es la IP de management del BIG-IP
  • Verificar que el puerto 443 está abierto: curl -k https://<IP>/mgmt/tm/sys/version
  • Verificar que el usuario tiene acceso a la API: -u admin:password

Error: 401 Unauthorized

Credenciales incorrectas o usuario sin permisos.
  • Verificar que ansible_password en vault es correcto
  • El usuario debe tener rol Administrator en el BIG-IP
  • Si el BIG-IP usa AD/LDAP, verificar f5_auth_provider

Error: Task X changed pero se esperaba ok

La tarea no es idempotente o el valor en group_vars difiere del configurado en el BIG-IP.
  • Revisar que los valores en group_vars coinciden con lo que ya tiene el dispositivo
  • Ejecutar con --check --diff para ver exactamente qué va a cambiar

DNS task se salta

  • Requiere f5_dns_servers | length >= 2 — definir al menos 2 servidores DNS
