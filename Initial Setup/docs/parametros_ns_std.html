DNS Servidores de Nombres (NS_STD_010)

Implementado en tasks/dns.yml usando el módulo bigip_device_dns.

CheckCampo APIVariable AnsibleDefaultTipo
NS_STD_010nameServersf5_dns_servers[]obligatorio
—searchf5_dns_search[]opcional
La tarea solo ejecuta si f5_dns_servers | length >= 2. Si defines menos de 2 servidores, la tarea se salta con skipped.

Ejemplo en group_vars

f5_dns_servers:          # obligatorio — mínimo 2
  - "10.10.1.53"
  - "10.10.2.53"
f5_dns_search:           # opcional — dominio de búsqueda
  - "corp.com"
  - "infra.corp.com"

Verificar en BIG-IP: list sys dns name-servers

HA High Availability / Clustering (NS_STD_004–009 · 018 · 019 · 028)

Fuera de scope de Initial Setup. La configuración del par HA (device group sync-failover, MAC masquerade del traffic-group-1, ha-order, ConfigSync IP y VLAN failsafe) ya no se aplica desde este playbook. Se realiza manualmente o mediante el proyecto TaskLBCommons (ha_setup.yml para el setup completo del par y ha_sync.yml para forzar la sincronización Active→Standby), que incluye validaciones previas (versión TMOS, NTP, licencia, Self-IPs flotantes) y cálculo automático del MAC masquerade.

Checks Fuera de Scope

CheckRazónAlternativa
NS_STD_027 Net route default — ruta del data plane, no del plano de gestión. El rol de Initial Setup no administra rutas de tráfico. Configurar manualmente en BIG-IP UI o en el playbook de red.
NS_STD_029 Certificado CN/SAN = hostname — es una validación, no una configuración. El rol no puede generar ni gestionar el ciclo de vida de certificados. Usar el playbook de gestión de certificados o renovar manualmente.
NS_STD_030 Certificado expiration ≤ 360 días — ídem al anterior. Validar en el playbook de Hardening (auditoría). Configurar alerta de expiración o automatizar renovación por separado.
