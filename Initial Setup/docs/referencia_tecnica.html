Arquitectura del Rol

El rol f5_initial_setup aplica hardening de seguridad en dispositivos F5 BIG-IP usando exclusivamente la colección f5networks.f5_modules y llamadas directas a la iControlREST API (fallback uri para endpoints sin módulo nativo). La autenticación de los módulos se maneja con el patrón f5_provider; las tareas uri usan un token iControlREST obtenido una sola vez por host (header X-F5-Auth-Token) y revocado al final.

Flujo de ejecución

El playbook corre completamente en localhost (el controller Ansible). Se conecta al BIG-IP via HTTPS contra el puerto de gestión. No se requiere SSH al dispositivo.
PasoDescripción
1Ansible carga defaults/main.yml como base de variables
2group_vars/ sobreescribe con valores del sitio
3tasks/main.yml orquesta los include_tasks por categoría
4Cada task file llama módulos nativos o uri para configurar el BIG-IP
5Todos los módulos son idempotentes: segunda ejecución → ok (sin cambios)

Los uri fallback se usan únicamente en endpoints donde no existe módulo nativo en la colección. Se autentican con el token iControlREST compartido (header X-F5-Auth-Token), obtenido una vez por host y revocado en el bloque always.

Secretos y Vault

Las credenciales sensibles nunca deben estar en texto plano. Se almacenan en inventory/group_vars/f5_devices.vault.yml y se encriptan con ansible-vault.

Variables a proteger con vault

VariableUso
ansible_passwordContraseña del usuario admin del BIG-IP
lb_snmpv3_<usuario>_auth_password / _priv_passwordContraseñas SNMPv3 — un par por cada usuario de f5_snmpv3_users

Comandos

# Crear archivo vault
ansible-vault create inventory/group_vars/f5_devices.vault.yml

# Encriptar archivo existente
ansible-vault encrypt inventory/group_vars/f5_devices.vault.yml

# Editar vault
ansible-vault edit inventory/group_vars/f5_devices.vault.yml
