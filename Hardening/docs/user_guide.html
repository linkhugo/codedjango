F5 BIG-IP Hardening Framework — Cómo ejecutar y usar el playbook de auditoría

1 Requisitos Previos

RequisitoDetalle
AnsibleVersión 2.10 o superior
Python3.8 o superior (requerido por Ansible)
Colecciones AnsibleNo se requieren colecciones externas (solo módulos built-in)
Acceso de redHTTPS al puerto 443 del management IP de cada F5
Credenciales F5Usuario con permisos de lectura (rol Operator o superior)
Sistema operativoLinux o macOS en el controller (Windows con WSL2)
Sin SSH al F5. El playbook realiza llamadas HTTPS a la API REST del dispositivo. No se requiere acceso SSH ni instalación de agentes en el F5.

2 Setup Inicial

  • Clonar o descargar el proyecto

    cd /ruta/deseada
git clone <repo-url> Hardening
cd Hardening

  • Configurar el inventario — Editar inventory/hosts.ini con los dispositivos F5:

    [f5_devices]
f5-primary    ansible_host=10.0.0.10   ansible_user=admin   ansible_connection=local
f5-secondary  ansible_host=10.0.0.11   ansible_user=admin   ansible_connection=local

  • Crear el archivo de credenciales

    # Copiar la plantilla
cp inventory/group_vars/f5_devices.vault.yml.example \
   inventory/group_vars/f5_devices.vault.yml

# Editar con el password real
nano inventory/group_vars/f5_devices.vault.yml

    El archivo debe contener:

    ansible_password: "TuPasswordAqui"

  • Cifrar el archivo de credenciales con ansible-vault

    ansible-vault encrypt inventory/group_vars/f5_devices.vault.yml
# Se pedirá una contraseña de vault — guárdala en lugar seguro

  • Verificar conectividad antes de ejecutar el playbook completo

    ansible f5_devices -m uri \
  -a "url=https://10.0.0.10/mgmt/shared/ping validate_certs=false" \
  --ask-vault-pass

    Debe responder con "ping": "pong".

3 Cómo Ejecutar el Playbook

Comandos frecuentes

ComandoDescripción
ansible-playbook hardening.yml --ask-vault-pass Auditoría completa con perfil CIS (hardening_v_1_5) en todos los dispositivos
ansible-playbook hardening.yml -e profile_name=network_services_std_values --ask-vault-pass Auditoría con perfil NS_STD (Network Services Standards)
ansible-playbook combined_audit.yml --ask-vault-pass Ambos perfiles en una sola ejecución → genera un CSV por dispositivo
ansible-playbook hardening.yml --limit f5-primary --ask-vault-pass Auditar solo un dispositivo específico del inventario
ansible-playbook hardening.yml -e country=MX --ask-vault-pass Usar directorio de salida configurado para México
ansible-playbook hardening.yml -e hardening_output_dir=/tmp/reportes --ask-vault-pass Guardar el CSV en una ruta personalizada
ansible-playbook hardening.yml -e f5_validate_certs=true --ask-vault-pass Producción: validar certificado TLS del F5
ansible-playbook hardening.yml -e lb_api_push=true -e lb_api_url=https://api.corp.com --ask-vault-pass Ejecutar y enviar resultados a la API Django automáticamente
Tip: Para no tener que escribir --ask-vault-pass cada vez, puedes configurar la contraseña de vault en el archivo ~/.vault_pass y agregar vault_password_file = ~/.vault_pass en ansible.cfg.

7 Resolución de Problemas

SíntomaCausa probableSolución
ERROR_CONN en todos los checks No hay conectividad al F5 en puerto 443 Verificar firewall, VPN y que el ansible_host sea correcto
ERROR_403 en checks El usuario no tiene permisos suficientes Asignar rol Operator o superior en el F5
Token inválido / expirado El playbook tardó más que f5_token_timeout Aumentar f5_token_timeout (máx F5: 36000 seg)
Error de vault al ejecutar Contraseña de vault incorrecta o archivo no cifrado Verificar con ansible-vault view inventory/group_vars/f5_devices.vault.yml
CSV vacío o no generado El directorio de salida no existe o sin permisos Crear el directorio o usar -e hardening_output_dir=/tmp
Checks SSH fallan con missing:KexAlgorithms El campo include del SSHD está vacío en el F5 Configurar sys sshd include con los algoritmos requeridos
2.6.3 falla aunque el usuario SNMP exista El nombre del usuario tiene capitalización diferente El check usa la colección /mgmt/tm/sys/snmp/users — verificar que el campo username tenga el valor "pruebas" (cualquier capitalización es válida)
NS_STD_029 siempre falla El certificado server.crt es el auto-firmado de F5 sin hostname correcto Instalar un certificado firmado con el CN igual al hostname del dispositivo
Playbook muy lento Muchos dispositivos en el inventario Usar --limit para auditar por lotes, o aumentar [ssh_connection] pipelining = True en ansible.cfg
Nota sobre certificados TLS: En entornos de laboratorio con certificados auto-firmados, mantener f5_validate_certs: false. En producción, usar -e f5_validate_certs=true y asegurarse de que la CA del F5 esté en el trust store del controller.
