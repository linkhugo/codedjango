F5 BIG-IP Hardening & Compliance Framework — Ansible + iControlREST

Resumen del Proyecto

Framework de auditoría y cumplimiento para dispositivos F5 BIG-IP basado en el CIS Benchmark (categorías 2.1–2.6) y controles de red estándar (NS_STD). Ejecuta checks de configuración vía la API REST de F5 (iControlREST) sin requerir acceso SSH al dispositivo, y genera reportes CSV automatizados.

AtributoValor
Plataforma destinoF5 BIG-IP TMOS (cualquier versión con iControlREST)
Ansible mínimo2.10
Conexión al dispositivoHTTPS puerto 443 (no SSH)
AutenticacióniControlREST token (POST /mgmt/shared/authn/login)
Perfiles disponibleshardening_v_1_5 (CIS), network_services_std_values (NS_STD)
OutputCSV por dispositivo + push opcional a API Django
Checks totales43 CIS + 28 NS_STD = 71 checks

Arquitectura

Sin SSH. Todas las tareas se ejecutan en el Ansible Controller. El F5 nunca recibe una conexión SSH — solo responde a llamadas HTTPS a su API REST. La variable ansible_connection: local en el inventario garantiza este comportamiento.

get_token.yml — Autenticación

Obtiene un token de sesión de iControlREST y extiende su duración.

PasoMétodoEndpointDatos
LoginPOST/mgmt/shared/authn/loginusername, password, loginProviderName
ExtenderPATCH/mgmt/shared/authz/tokens/{token}timeout: f5_token_timeout

El token se almacena en el fact f5_api_token (marcado no_log: true) y se usa como header X-F5-Auth-Token en todas las llamadas siguientes.

execute_action.yml — Consulta y Extracción

Para cada check, realiza una llamada GET a item.api_path y extrae el valor del campo item.campo.

Lógica de extracción de campo

  1. Si la respuesta contiene items[] (colección), itera sobre cada objeto
  2. Navega la ruta dot-separated de campo (ej: parent.child)
  3. Convierte todo a minúsculas y une con espacios → valor_raw
  4. Si display_keyword está definido: extrae la línea que contiene la keyword y toma el valor tras ella
  5. Si display_line está definido: toma la línea completa que coincide
  6. Tokeniza: divide por espacios/comas → valor_lista

Manejo de errores API

Condiciónvalor_raw resultante
Conexión fallidaERROR_CONN
HTTP 404ERROR_404
HTTP 403ERROR_403
Keyword no encontradamissing:{keyword}

Los errores de API no abortan el playbook (ignore_errors: true). El check se marca como failed automáticamente si el valor contiene ERROR_.

policy_engine.yml — Evaluación de Reglas

Evalúa la lista de reglas del check. Por defecto el resultado es passed; si alguna regla falla, cambia a failed. Múltiples reglas actúan como AND (todas deben pasar).

TipoFalla cuando…Parámetros
allow_anyNingún valor de values aparece en valor_listavalues: [...]
denyAlgún token de values aparece en valor_listavalues: [...]
deny_containsAlgún token coincide con el regex patternpattern: "sha1|md5"

allow_onlyAlgún token no está en valuesvalues: [...]

revoke_token.yml — Logout

Se ejecuta en el bloque always: de main.yml, garantizando que el token se revoca incluso si un check falla a mitad de la ejecución.

MétodoEndpointStatus aceptados
DELETE/mgmt/shared/authz/tokens/{f5_api_token}200 (éxito), 404 (token ya expirado)
El guard when: f5_api_token is defined protege contra el caso en que get_token.yml haya fallado y el token nunca se obtuvo.

push_to_api.yml — Integración Django

Función opcional activada con -e lb_api_push=true. Envía cada resultado a una API Django REST.

PasoEndpointDescripción
1. LoginPOST /api/v1/token/Obtiene JWT Bearer token
2. PushPOST /api/v1/hardening/checks/Un POST por cada check (body: device, code, resultado, fecha…)

Requiere: lb_api_url, lb_api_user, lb_api_pass (los últimos dos en vault).

Schema de un Check

checks:
  - categoria: "2.1"              # Agrupación (visible en reporte)
    code: "2.1.1"                 # Identificador único (clave en CSV)
    descripcion: "Status Policy"  # Descripción legible
    cmd: "list auth password-policy ..."  # Referencia tmsh (solo informativo)
    api_path: "/mgmt/tm/auth/password-policy"  # Endpoint GET iControlREST
    campo: "policyEnforcement"    # Clave JSON a extraer (dot-path soportado)
    valor_recomendado: "enabled | modify auth password-policy ..."

    # Opcionales — para respuestas multi-línea (ej: sshd include)
    display_keyword: "KexAlgorithms"   # Extrae valor tras esta keyword en la línea
    display_line: "FileETag"           # Extrae línea completa que coincida

    policy:
      - type: allow_any
        values: ["enabled"]
      - type: numeric_gte
        value: 15

Consideraciones de Seguridad

ÁreaImplementación
CredencialesAlmacenadas en ansible-vault (AES-256); nunca en texto plano en el repo
LoggingTareas con credenciales usan no_log: true (no aparecen en output)
Token lifecycleToken creado → extendido → revocado siempre (bloque always:)
TLSf5_validate_certs: false por defecto (labs); usar true en producción
Permisos F5Usuario de auditoría con rol mínimo de Operator es suficiente (solo GET)
API DjangoAutenticación JWT per-run; credenciales en vault
